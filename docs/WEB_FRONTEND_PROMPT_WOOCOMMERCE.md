# Веб‑фронтенд: приём новых данных из WooCommerce

## Цель
Обновить веб‑фронтенд, чтобы корректно принимать и отображать новые столбцы из Excel отчёта сравнения цен, связанные с остатками и ценами из WooCommerce (DimKava).

## Источник данных
- Файл выгрузки: `data/output/price_comparison_YYYYMMDD_HHMMSS.xlsx` (загружается через `upload_data.py` на `API_UPLOAD_URL` с заголовком `X-API-Key`).
- Основной лист: `COMPARISON`.
- Дополнительный лист: `INVENTORY` (содержит те же новые поля для кросс‑проверки).

## Новые столбцы (COMPARISON)
- `DIM_KAVA_STOCK` — остаток из WooCommerce API (`stock_status='instock'`, значение `stock_quantity`, `-` если нет матча).
- `DIM_KAVA_WC_PRICE` — цена из WooCommerce:
  - Если есть скидка (`sale_price` > 0): `regular_price \ sale_price` (два числа через обратный слэш).
  - Иначе: `regular_price` как одно число.
  - Если нет матча или цены: `-`.

## Логика формирования
- Матчинг с инвентарём по модели (нормализация удаляет EU/цветовые суффиксы).
- Fuzzy matching для WooCommerce включён (confidence >= 0.9).
- Дополнительный fallback: попытка найти WooCommerce товар по названию для моделей из скрапера DimKava (если нет модели у WC‑товара, но имя содержит базовую модель и совпадает бренд).

## Что нужно учесть на фронтенде
1) Парсинг Excel:
   - Считать столбцы `DIM_KAVA_STOCK` и `DIM_KAVA_WC_PRICE` как строки/числа; пустые значения представлены символом `-`.
   - На листе `INVENTORY` те же поля присутствуют для товаров инвентаря.
2) Отображение:
   - Показать два новых столбца в таблице сравнения.
   - В `DIM_KAVA_WC_PRICE` при формате `1234.00 \ 999.00` отображать оба числа (обычная/акционная).
   - Для `-` выводить прочерк или «нет данных».
3) Фильтрация/поиск:
   - Поддержать фильтры по наличию стока (`DIM_KAVA_STOCK` != '-') и по диапазону стока/цен (по желанию).
4) API/безопасность:
   - Реальные креды WooCommerce остаются в `.env` backend‑части; фронту ничего добавлять не нужно.
   - Загрузка файла как и раньше: `upload_data.py` → `API_UPLOAD_URL` с `API_KEY`.
